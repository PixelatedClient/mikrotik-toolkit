## The problem VXLAN solves

Traditional VLANs (Layer 2 in Depth track) are limited to 4094 IDs and don't cross routed boundaries — a VLAN can't span two data centres connected only by routed links without a tunnel of some kind. Large data centres and multi-tenant clouds need far more than 4094 isolated segments, and need those segments reachable across a routed (Layer 3) core rather than one big fragile spanning-tree domain.

## What VXLAN actually does

VXLAN (**Virtual Extensible LAN**) wraps an entire Ethernet frame — including its original header — inside a UDP packet, and sends that UDP packet across an ordinary routed IP network. The receiving end unwraps it and delivers the original frame as if it had arrived on a local switch port. This is why VXLAN is called an **overlay**: a Layer 2 network logically laid on top of a Layer 3 network that has no idea it's carrying Ethernet frames at all, only UDP packets between two IP endpoints.

Two ideas make this work:

- **VNI (VXLAN Network Identifier)**: a 24-bit segment ID, VXLAN's answer to the VLAN's 12-bit limit — about 16 million segments instead of 4094.
- **VTEP (VXLAN Tunnel Endpoint)**: the device (physical switch or virtual switch on a hypervisor) that wraps and unwraps frames at each end of the tunnel. Two VTEPs on the same VNI, however many routed hops apart, behave like they're on the same Layer 2 segment.

## The control-plane gap, and EVPN

Original VXLAN had no built-in way for VTEPs to learn where a given MAC address lives — it relied on flooding unknown traffic to every VTEP (via multicast or a manually configured list), which doesn't scale and behaves a lot like the flooding problem plain switching already has.

**EVPN (Ethernet VPN)** fixes this by using BGP (Advanced Routing track) as VXLAN's control plane: VTEPs advertise "this MAC address is reachable through me" as a BGP update, the same way a router advertises a reachable prefix. Other VTEPs learn MAC reachability from BGP instead of from flooding, which is why EVPN pairs with VXLAN so often in modern data-centre design — it directly reuses BGP's proven scaling to solve VXLAN's missing control plane, instead of inventing a new protocol.

## Where this fits

VXLAN with an EVPN control plane is the standard modern replacement for stretching VLANs across a data centre fabric or between data centres — it gives the segment scale VLANs can't (16 million vs 4094), keeps the core a plain routed IP network (avoiding a fabric-wide spanning tree domain), and uses BGP, an already well-understood protocol, to distribute MAC reachability instead of relying on flooding.
