## Why default timers are slow

Routing protocols learn a neighbour is gone only when keepalives stop:

- **BGP**: RouterOS's own default is a 3-minute (180 s) hold time — RFC 4271 sets no specific number, only a 3-second minimum, so this is a RouterOS/industry default rather than a protocol requirement; other vendors commonly default to 90 s instead, so always check what you're actually running.
- **OSPF**: RouterOS's default dead-interval is 40 s on broadcast networks — "four times" the default 10 s hello-interval.

If a link fails without the interface going down (a media converter, a switch in between, a one-way fibre fault), you lose traffic for that whole time. For voice, video or a customer SLA that is too long.

## BFD

**Bidirectional Forwarding Detection** — RFC 5880 describes it as detecting "faults in the bidirectional path between two forwarding engines... with potentially very low latency," independent of the routing protocol, media type or data protocol running over that path. It sends small packets every few hundred milliseconds. If several are missed, BFD declares the path down and tells the routing protocol immediately.

Timing, per RFC 5880:

```
detection time = negotiated transmit interval x Detect Mult
```

For example 300 ms x 3 = 900 ms.

## Configuring on RouterOS

```
/routing bfd configuration add interfaces=ether1 min-rx=300ms min-tx=300ms multiplier=3
```

This project confirmed on a real RouterOS 7.16 router that `use-bfd=yes` alone is not enough — the session stays inactive ("BFD forbidden for interface") until a matching `/routing bfd configuration` entry exists, and that the `ms` units above are exactly what the router expects. Then enable it per protocol:

```
# BGP
/routing bgp connection set upstream use-bfd=yes

# OSPF
/routing ospf interface-template set [find networks=10.0.12.0/30] use-bfd=yes
```

Both ends must enable BFD, or nothing is detected.

## Choosing timers

Aggressive timers detect failures faster and also cause **false positives** on a busy or CPU-limited router: a brief spike drops a session and a flap follows. Start at 300 ms x 3 for core links. Use more relaxed timers for slow or shared paths.

## Design for fast convergence

Detection is only the first step. Convergence = detection + propagation + recompute + FIB update. Improve it by:

- **ECMP**: equal-cost paths keep forwarding while others reconverge.
- **Redundant links** in rings or meshes with the IGP cost set deliberately.
- **Loopback iBGP** so a link failure does not tear down sessions.
- **Fewer routes** on edge devices: aggregate.
- **Graceful restart** where the platform supports it, for planned maintenance.

## Measure it

Use a lab: run a continuous ping across the path, pull a cable, and count the lost packets.

```
/ping 192.168.3.1 interval=100ms
```

At 100 ms intervals, N lost packets is about N x 0.1 s of outage. Repeat with BFD on and off to see the difference.
