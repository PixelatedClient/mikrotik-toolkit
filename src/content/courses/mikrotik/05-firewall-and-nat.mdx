## Packet flow

RouterOS processes packets through fixed chains:

- **prerouting** (raw, mangle, dstnat): before the routing decision.
- **input**: destined for the router.
- **forward**: passing through.
- **output**: generated by the router.
- **postrouting** (srcnat): after routing.

Rules in a chain run top to bottom; the first terminating match wins. Print with counters to see what is hit:

```
/ip firewall filter print stats
```

## A solid input chain

```
/ip firewall filter
add chain=input action=accept connection-state=established,related,untracked
add chain=input action=drop connection-state=invalid
add chain=input action=accept protocol=icmp
add chain=input action=accept src-address-list=mgmt
add chain=input action=drop comment="drop everything else"
```

## Address lists

Group addresses once, reuse everywhere:

```
/ip firewall address-list add list=mgmt address=192.168.88.0/24
/ip firewall address-list add list=mgmt address=10.99.0.0/24
```

Lists can be edited without touching the rules, and can expire entries automatically with `timeout=`.

## Source NAT

```
/ip firewall nat add chain=srcnat action=masquerade out-interface-list=WAN
```

Use `masquerade` when the WAN address changes (DHCP, PPPoE): MikroTik's own documentation notes the router "will clear all masqueraded connection tracking entries related to the interface" whenever that interface's address changes, which is exactly the recovery behaviour you want after a DHCP renewal or PPPoE reconnect. With a fixed address, `action=src-nat to-addresses=...` is slightly cheaper.

## Port forwarding

```
/ip firewall nat add chain=dstnat action=dst-nat protocol=tcp dst-port=8080 \
    in-interface-list=WAN to-addresses=192.168.88.10 to-ports=80
```

The forward chain must also allow it. The gateway config in this course drops new WAN connections that are **not** dst-natted, so forwarded ports work without an extra allow rule.

### Hairpin NAT

LAN clients reaching the server via the public address need a masquerade for that traffic:

```
/ip firewall nat add chain=srcnat action=masquerade src-address=192.168.88.0/24 \
    dst-address=192.168.88.10 protocol=tcp dst-port=80
```

## The raw table

`raw` runs before connection tracking, so dropping there is cheap — MikroTik's documentation describes it as letting you "selectively bypass or drop packets before connection tracking, that way significantly reducing the load on the CPU." Use it against floods and for exempting heavy traffic from tracking:

```
/ip firewall raw add chain=prerouting action=drop src-address-list=blocklist
```

## FastTrack

`fasttrack-connection` lets established connections bypass most of the firewall for speed. MikroTik's documentation is specific about the cost: a fast-tracked packet bypasses "firewall, connection tracking, simple queues, queue tree with parent=global, ip traffic-flow, IP accounting, IPSec, hotspot universal client, VRF assignment" — it is fine for simple routers, but skips queues and further mangle/filter rules entirely, so do not enable it where you shape traffic or need every packet to still be inspected.

## Debugging

```
/ip firewall connection print where dst-address~"8.8.8.8"
/log print where topics~"firewall"
```

Add a temporary rule with `action=log log-prefix=DBG` above the suspect one, then check the log. Remove it afterwards.
