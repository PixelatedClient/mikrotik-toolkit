## What SNMP does

SNMP (Simple Network Management Protocol) lets a manager **poll** values from devices and receive **traps** when something happens. Values live in a tree called the **MIB**, addressed by **OIDs**.

Common operations:

- **GET / GETNEXT / GETBULK**: read.
- **SET**: write (avoid; most networks never need it).
- **TRAP / INFORM**: the device tells the manager of an event.

## Versions

| Version | Security |
|---|---|
| v1 / v2c | A **community string** in plain text. Treat it as a weak password, restrict by source IP |
| **v3** | Usernames replace the community string, with three security levels RFC 3411 defines: no authentication and no privacy, authentication only, or authentication with privacy (encryption). Use the strongest level you can |

## Useful OIDs

| Data | OID |
|---|---|
| System uptime | `1.3.6.1.2.1.1.3.0` |
| Interface name | `1.3.6.1.2.1.31.1.1.1.1` (ifName) |
| Interface operational status | `1.3.6.1.2.1.2.2.1.8` |
| Input octets, 64-bit | `1.3.6.1.2.1.31.1.1.1.6` (ifHCInOctets) |
| Output octets, 64-bit | `1.3.6.1.2.1.31.1.1.1.10` (ifHCOutOctets) |

Always use the **64-bit** counters (`ifHC*`). RFC 2863 introduced them for exactly this reason — the older 32-bit `ifInOctets`/`ifOutOctets` wrap far too quickly on a fast link (the RFC's own example: about 57 minutes at just 10 Mbps), giving false spikes and missing data on anything faster.

## Turning counters into rates

Counters only grow. To get a rate, poll twice:

```
rate (bit/s) = (counter_now - counter_before) x 8 / seconds_between
```

Handle wraparound and device reboots (the counter resets to zero): discard negative deltas.

Poll every 30-60 s on important links and 5 min elsewhere. Slow polling hides short bursts.

## MikroTik

```
/snmp set enabled=yes contact="noc@example.net" location="POP-1"
/snmp community set [find default] name=nocmon addresses=192.0.2.50/32 read-access=yes write-access=no
```

For v3 add a community with authentication and encryption:

```
/snmp community add name=noc-v3 security=private \
    authentication-protocol=SHA1 authentication-password="long-auth-secret" \
    encryption-protocol=AES encryption-password="long-crypt-secret" \
    addresses=192.0.2.50/32 read-access=yes write-access=no
```

Verify the property names on your version, and allow UDP 161 from the collector only in the input firewall.

## Test from a Linux host

```
snmpwalk -v2c -c nocmon 192.0.2.1 1.3.6.1.2.1.1
snmpget  -v2c -c nocmon 192.0.2.1 1.3.6.1.2.1.31.1.1.1.6.1
```

## What to monitor

- **Interfaces**: utilisation, errors, discards, operational state.
- **Device health**: CPU, memory, temperature, PSU.
- **Optics**: transceiver power (DOM/DDM) on uplinks.
- **BGP/OSPF**: session state changes, via traps or logs.

## Alerting

- Alert on **symptoms with meaning**: link down, sustained utilisation above 80%, rising errors, BGP neighbour down.
- Avoid alerting on every CPU spike.
- Add **dependencies**: if the router is down, do not page for every device behind it.
- Send traps to a syslog or alert manager the on-call person actually reads.
